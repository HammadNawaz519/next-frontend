2. REQUESTS THAT REMAIN ON VERCEL & JUSTIFICATION
--------------------------------------------------------------------------------
1. `GET /`, `GET /dashboard`, `GET /accounts`, `GET /security`: Static and Client-Side Next.js route delivery. Served directly from Vercel Global Edge CDN.
2. `POST /api/auth/[...nextauth]`: NextAuth credentials and Google OAuth authentication provider. Manages secure cryptographic session signing and JWT issuance.
3. `POST /api/register`, `POST /api/verify-email`, `POST /api/resend-code`, `POST /api/forgot-password`, `POST /api/reset-password`: Email OTP validation and password resets using Nodemailer Gmail SMTP.
4. `POST /api/transcribe`: Speech-to-text audio transcription gateway to Groq Cloud Whisper API.
5. `GET /api/music/search`: Music clip preview search proxying Apple iTunes and Deezer APIs with 24-hour ISR caching.

3. RENDER API SUITE TO BE IMPLEMENTED (`Web/Server/index.js`)
--------------------------------------------------------------------------------
- Base URL: `process.env.NEXT_PUBLIC_SOCKET_URL || process.env.NEXT_PUBLIC_BACKEND_URL || 'https://server-production-265c.up.railway.app'`
- Authentication: `verifyAuth` middleware extracting and validating JWT tokens or session authorization headers.
- Endpoints:
  1. `GET /api/health` & `GET /ping`
  2. `GET /api/turn-credentials`
  3. `GET /api/social/initial-data`
  4. `GET /api/social/recent-chats`
  5. `GET /api/social/messages` (query: `otherUserId`, `limit`, `beforeId`)
  6. `POST /api/social/messages` (body: `{ receiverId, content, type, ... }`)
  7. `DELETE /api/social/messages/:id` (body: `{ deleteFor: 'me' | 'everyone' }`)
  8. `POST /api/social/messages/react` (body: `{ messageId, emoji }`)
  9. `GET /api/social/search` (query: `q`)
  10. `GET /api/social/profile/:userId` & `GET /api/social/profile`
  11. `PUT /api/social/profile` (body: `{ name, bio, website, image, phone, isPrivate }`)
  12. `PUT /api/social/username` (body: `{ username }`)
  13. `GET /api/social/stories` & `POST /api/social/stories` & `DELETE /api/social/stories/:id`
  14. `GET /api/social/nicknames` & `PUT /api/social/nicknames` (body: `{ targetId, nickname }`)
  15. `GET /api/social/calls` & `POST /api/social/calls` (body: `{ receiverId, type, status, duration }`)
  16. `GET /api/social/media/:otherUserId`
  17. `POST /api/accounts/validate` (body: `{ accounts: [...] }`)

4. DATABASE CONNECTION & INDEXING STRATEGY ON RENDER
--------------------------------------------------------------------------------
- Database Engine: PostgreSQL on Aiven Cloud / Supabase.
- Connection: Singleton `pg.Pool` with `max: 10`, `idleTimeoutMillis: 300000`, `connectionTimeoutMillis: 8000`.
- Composite Indexes:
  * `SocialMessage`: `(senderId, receiverId, createdAt)`, `(receiverId, senderId, createdAt)`, `(receiverId, isSeen, deletedByReceiver)`, `(senderId, deletedBySender, createdAt)`, `(senderId, receiverId, type, createdAt)`
  * `SocialCall`: `(callerId, createdAt)`, `(receiverId, createdAt)`
  * `Story`: `(userId, createdAt)`
  * `Post`: `(userId, createdAt)`, `(postType, createdAt)`
  * `User`: GIN Trigram indexes on `username` and `email` (`idx_user_username_trgm`, `idx_user_email_trgm`)

--------------------------------------------------------------------------------
5. FRONTEND CENTRALIZED CLIENT (`Web/Frontend/lib/render-api-client.ts`)
--------------------------------------------------------------------------------
- Purpose: Directs all client requests from `SocialChat`, `ProfilePanel`, `SongPickerModal`, etc., directly to the Render backend.
- Cold-Start Resilience: Configured with exponential backoff retries (3 attempts: 500ms, 1500ms, 3000ms) with idempotency keys for mutations.
- Request Coalescing: In-flight deduplication prevents redundant parallel GET queries for the same resources.
- Zero UI Modifications: Strict UI preservation across all components.
